# 12. Known Limitations and Correctness Caveats

*Part of the [KMX SAT Solver technical reference](README.md).*

| # | Limitation | Impact | Where |
| ---: | :--- | :--- | :--- |
| 1 | **BVE is unsound under incremental use.** A clause added over an eliminated variable after a solve has nothing to contradict it | Next episode can answer satisfiable on an unsatisfiable formula | [§6.5](06-simplification.md#65-bounded-variable-elimination-and-why-it-is-off-by-default) |
| 2 | **BVE fails on larger formulas.** Pigeonhole 11/10 reported satisfiable with `--enabled-pass-mask 64`; correct at 9 holes and below | Size-dependent unsoundness of unknown cause | [§6.5](06-simplification.md#65-bounded-variable-elimination-and-why-it-is-off-by-default) |
| 3 | `balanced` and `aggressive` profiles enable every pass, BVE included | Those profiles inherit limitations 1 and 2 | [§10.2](10-configuration.md#102-configuration-profiles) |
| 4 | **Five simplification passes are scaffolding** (`blocked`, `covered`, `fast`, `instantiation`, `sweep`) | Their counters report activity that did not occur; no formula change | [§6.1](06-simplification.md#61-simplification-pass-inventory) |
| 4d | **Factoring is skipped while a proof consumer is attached** | Its added clauses are RAT on the fresh variable; the DRAT tracer could take them (pivot first) but the LRAT checkers need hints the pass does not produce, so a proof-logging run does not get the pigeonhole speed-up | [§6.1](06-simplification.md#61-simplification-pass-inventory) |
| 4f | **Failed-literal probing is skipped while a proof consumer is attached** | Its units are RUP steps without antecedent chains, which the LRAT consumers require; the search derives the same units with chained analysis, only later | `probe_failed_literals` |
| 4i | **XOR-chain formulas are searched, not refuted at the root** (`dubois*`, and every XOR-heavy encoding) | Kissat and CaDiCaL 3 refute `dubois100` with zero conflicts by congruence closure over extracted XOR gates; kmx-sat's `congruence` pass depends on the unsound equivalent-literal substitutor (4a) and is off, so it searches 1,551 conflicts and stays behind both on these two-millisecond runs | [§6.4](06-simplification.md#64-the-implemented-passes) |
| 4h | **`hole9` lost phase luck** | The lucky check now restores its phases on every formula; on this unsatisfiable pigeonhole the search from the entry phases takes 15.8k conflicts instead of 9.3k (61 → 107 ms), while the same change lifts `bmc-ibm-13` 0.51 → 0.22 s | [§5.2](05-branching-and-scheduling.md#52-phase-selection-and-local-search-seeding) |
| 4g | **Regression coverage of the 2026-09-06 defects** | `regression_soundness_test`, `reduce_protection_test` and `pass_equivalence_test` pin every defect of the four optimization cycles, including a 400-formula exhaustive check of the whole pre-search pipeline; the sixth cycle added the first phase's early decision and exact restore and the walk gate | [§11.2](11-build-test-benchmark.md#112-tests) |
| 4e | **A proof consumer attached after clauses were added gets ids in database order** | Events are not dispatched while no consumer exists; on attachment every live clause is adopted, so an LRAT proof of a session that attached its tracer late numbers the originals in database order rather than input order. Attach before adding clauses for checkable LRAT | `proof_manager::adopt_clause` |
| 4a | **Equivalent-literal substitution is unsound** (`equivalence_substitutor`, used by `decomposition` and `congruence`): variables are merged without polarity, rewritten clauses keep duplicate literals, and no reconstruction witness is recorded | A satisfiable `bmc-ibm-13` was answered with a model violating one clause; both passes are now off by default and stay opt-in until fixed | [§6.1](06-simplification.md#61-simplification-pass-inventory) |
| 4b | `transitive_reducer` let a binary clause removed earlier in the pass justify further removals | Unsatisfiable `bf0432-007` and `bf2670-001` were answered SAT; **fixed** on 2026-09-06 (removed clauses no longer contribute edges; the pass is also effort-bounded) | [§6.1](06-simplification.md#61-simplification-pass-inventory) |
| 4c | `forward_subsumer` deleted original clauses subsumed by learned clauses, which reduction could later remove | `hole9`, `hole10`, `bmc-ibm-12` and `bmc-ibm-13` were answered with models violating a deleted original clause; **fixed** on 2026-09-06: a learned clause that subsumes an original one is promoted to irredundant first (`database::make_irredundant`) | [§6.4](06-simplification.md#64-the-implemented-passes) |
| 5 | `controller::rephase` is unimplemented and unwired | Diversification comes from the local-search re-walks only | [§5.2](05-branching-and-scheduling.md#52-phase-selection-and-local-search-seeding) |
| 6 | **IPASIR is a 7-function subset**; `ipasir_signature`, `ipasir_set_terminate`, `ipasir_set_learn` are absent, as is all of IPASIR-UP | Stock IPASIR harnesses will not link | [§2.3](02-public-api.md#23-ipasir-c-abi) |
| 7 | The arena's 4 GB `mmap` path is Linux-only; elsewhere it degrades to a growable vector | Loses the zero-reallocation guarantee off Linux | [§3.1](03-memory-architecture.md#31-virtual-memory-arena-bankarena) |
| 8 | The glue-EMA restart trigger is disabled by default (`glue_restart_threshold_percent = 0`) | Restarts are Luby-scheduled only; enabling the trigger measured worse on random 3-SAT | [§5.3](05-branching-and-scheduling.md#53-restarts-controllerrestart) |
| 9 | `differential_campaign.py` tops out around 40 variables and never adds clauses post-solve | It passed 300/300 while two real unsoundness defects were live | [§6.5](06-simplification.md#65-bounded-variable-elimination-and-why-it-is-off-by-default) |
| 10 | `forward_subsumer` at preprocessing is unbounded (24% of the `gcp250_15` run); `transitive_reducer` and `probing` are now linear or effort-bounded | Large structured formulas still pay a subsumption cost that usually removes nothing | [§11.3](11-build-test-benchmark.md#113-benchmarks) |
| 11 | **`cdcl::witness_checker` is dead code on the shipped path** (only its unit test constructs one). Independent model checking exists only in the CLI | A library embedder gets no model verification unless it writes its own | [§6.6](06-simplification.md#66-model-reconstruction-and-witness-verification) |
| 12 | **The whole `runtime` namespace is scaffolding** except `controller::signal`, which nothing polls | No portfolio, no parallel preprocessing, no clause sharing; `Ctrl-C` is not handled by the library | [§9.2](09-io-runtime-telemetry.md#92-runtime-kmxsatruntime) |
| 13 | Six headers compile and link but nothing on the shipped path includes them (`external_frontend`, `failed_core_extractor`, `garbage_collector`, `compaction_service`, `otf_strengthener`, `assumption_reuse_advisor` — since the header/source split each has a translation unit and a unit test, which is all that includes it), and seven more are superseded by the in-core engine (`conflict_analyzer`, `clause::minimizer`, `clause::learner`, `engine::backtrack`, `engine::decision`, `vmtf_queue`, `chb_tracker`) | Doc comments describe an architecture wider than the one that runs | [§1.5](01-overview.md#15-declared-but-unwired-components) |
| 14 | `io::dimacs_parser` and the CLI's inline parser are **two separate implementations** | A parsing fix in one does not reach the other | [§9.1](09-io-runtime-telemetry.md#91-io-kmxsatio) |
