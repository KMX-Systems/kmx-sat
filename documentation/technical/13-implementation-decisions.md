# 13. Implementation Decisions Matrix

*Part of the [KMX SAT Solver technical reference](README.md).*

Each record carries a **source** for its stated impact: *measured* (a number traceable to a source comment
or a benchmark log in this repository), or *design* (a structural rationale not separately benchmarked).
Treat the two differently when deciding whether to revisit a decision.

| ID | Subsystem | Choice | Alternatives considered | Rationale and impact | Source |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **DEC-01** | Architecture | Composition root over concrete classes | Monolithic `Internal` struct (CaDiCaL), C global struct (Kissat) | Independent unit testing of BCP, conflict analysis, and heuristics while keeping a flat layout | design |
| **DEC-02** | Hot path | No virtual functions; `cpp.enableRtti: false` | Interface inheritance (`virtual status propagate()`) | Virtual dispatch disrupts branch prediction and blocks inlining in the BCP loop | design |
| **DEC-03** | Memory | 4 GB virtual bump arena via `mmap` | `std::vector`, or `malloc` per clause | Reservation costs no physical RAM; no reallocation, no clause copying, no latency spikes during derivation | design |
| **DEC-04** | Clause layout | Contiguous 16-byte header + literals | Separate `vector<clause_metadata>` table | Metadata and both watched literals land in one cache line instead of two random accesses | design |
| **DEC-05** | References | 32-bit `ref_t` offsets | 64-bit `clause*` | Halves the pointer footprint in watch lists and reason arrays; also survives relocation, which a pointer cannot | design |
| **DEC-06** | Propagation | In-place two-pointer watch compaction | Temporary lists or `erase()` passes | No vector churn in the hottest loop; drop-vs-retain costs one index increment | design |
| **DEC-07** | Propagation | Blocking-literal fast path | Fetch clause literals immediately | Dismisses a satisfied clause without touching liveness flags or the clause body — the majority of ~97M watch visits on a `uuf250` solve | measured (source comment) |
| **DEC-08** | Conflict analysis | Implication-graph 1-UIP resolution | Chronological backtracking | Non-chronological backjumping cut aim100 conflicts 956 → 32 and decisions 999 → 206 | measured (historical log) |
| **DEC-09** | Minimization | Allocation-free stamped arrays | `std::unordered_set<variable>` | Rebuilding hash sets per conflict made `malloc` ~12% of runtime | measured (historical log) |
| **DEC-10** | Branching | EVSIDS primary, VMTF fallback | VMTF-first, or pure VSIDS | On random 3-SAT (r3_200), consulting EVSIDS before VMTF cut conflicts 344,408 → 27,106 | measured (historical log) |
| **DEC-11** | Phase selection | WalkSAT local-search seeding | Random or static phase bias | `satlib_uf250_01` 1380 ms → 5 ms; seven 350–600 var satisfiable instances from all unsolved at 30 s to 0.61 s total | measured (benchmark log) |
| **DEC-12** | Reduction | Three glue tiers, recomputed each pass | Two tiers, or pure activity ranking | Recomputing from current glue matters because minimization lowers glue after birth; interval sweep 400 → 16.0 s, 4000 → 7.5 s, 16000 → 11.2 s | measured (source comment) |
| **DEC-13** | Restarts | Luby base 4096 + optional glue EMA | Fixed cadence, or restarts disabled | Luby growth preserves completeness; base sweep 1024 → 10.8 s, 4096 → 7.5 s, 8192 → 7.7 s | measured (source comment) |
| **DEC-14** | Subsumption | 64-bit signature + rarest-literal traversal | Nested linear scans | One register instruction disproves most candidate pairs; the rarest list is complete and far shorter | design |
| **DEC-15** | Proof tracing | Closed `std::variant` dispatch (`tracer::view`) | Abstract base `IProofTracer` | Runtime format selection with no vtable — mandatory, since RTTI is off | design |
| **DEC-16** | Proof tracing | Logical IDs decoupled from physical offsets | Use `ref_t` as the clause ID | Clauses relocate during GC; stable `proof::clause::id` keeps LRAT antecedent chains sound | design |
| **DEC-17** | Proof tracing | Antecedents built only with a consumer attached | Always build the chain | Costs a stable-id lookup and a duplicate scan per resolution step, once per conflict, for nothing in the default configuration | design |
| **DEC-18** | Simplification | BVE excluded from the default pass set | Enable it for the structured-instance win | The win is real (XOR chain 0.16 s → 0.01 s) but the pass is unsound incrementally and on larger formulas | measured + correctness |
| **DEC-19** | Build | `-O3 -flto=auto`, no `-Ofast`, no `-march=native` | `-Ofast`, `-march=native` | `-ffast-math` breaks EMA/activity FP semantics and measured as no gain; `-march=native` breaks reproducibility of the clean-checkout gates for no measured gain | measured (build comment) |
| **DEC-20** | I/O | 64 KB-buffered `fread` integer parser | `std::ifstream` + `std::istringstream` | Reading tiny DIMACS instances dropped 4.08 ms → 2.22 ms by eliminating string allocation and stream sync | measured (historical log) |
| **DEC-21** | Hot path | Literal-indexed values, 8-byte watches, no liveness test, reasons marked per pass, heap invariant | The previous component-callback engine | `uuf250_01`: 23.9 G → 4.7 G instructions, 137 k → 96 k conflicts; propagation ~40 instructions per visit | measured (callgrind, 2026-09-06) |
| **DEC-22** | Analysis | In-core 1-UIP with recursive minimization and stamps; clause stored once, minimized | Callback-driven analyzer plus post-hoc shrink with hash containers | Removed five hash operations and a vector copy per conflict; LRAT chains built only with a consumer | measured (callgrind) |
| **DEC-23** | Incrementality | Assumptions as decision levels 1..k | Level-0 assumptions | The level-0 design leaked assumption-derived clauses into later episodes (reproduced: satisfiable episode answered UNSAT) | correctness |
| **DEC-24** | Local search | probSAT + low-noise WalkSAT portfolio, opening walk of 4,000 flips/var in rounds, adaptive re-walks at restarts | One WalkSAT walk of 4,000 flips/var | Solves `lran_f2000` and `gcp125_17`, unsolved by either reference; ≤ a few percent on unsatisfiable formulas | measured (corpus + held-out) |
| **DEC-25** | Reduction | Every 1,000 conflicts, 75% of candidates, keyed sort, in-place compaction | 4,000 / 50%, comparator sort, no compaction | −19% on the held-out unsatisfiable set; arena stays compact | measured (held-out) |
| **DEC-28** | Local search | Opening walk after a 2,000-conflict probe, capped at 10 M flips; re-walk floor capped at 1 M flips; walker prepared on the original formula; introduced variables phased from their groups | Walk first, budget by variable count alone | Structured classic set 38 s → 4.4 s with the hard set unchanged; the walk's own trajectory on the winners is preserved by starting it from the entry phases | measured (classic, hard, held-out) |
| **DEC-29** | Reduction | Recently used clauses are not candidates; mid-glue used clauses get one pass of grace; interval stays fixed | Growing interval (arithmetic or square-root) | Growth halved `hole9`/`bmc-ibm-12` but cost the held-out set 9–20%; protection gives the same gain at no cost there (10.42 s → 10.44 s) | measured (heavy, held-out, repeated) |
| **DEC-30** | Simplification | Bounded variable addition (`factorizer`) in the default pipeline, with the selector's binary-density gate removed; effort 4 visits per clause, clauses of at most 5 literals, two rounds | Keep the stub; gate factoring off binary-dense formulas | Binary-dense formulas are exactly where it pays: `hole9` 3.8 s → 0.12 s, `hole10` timeout → 1.1 s, matching Kissat's conflict counts (Kissat needs 289,997 conflicts on `hole9` with its factoring off); the tight effort keeps it from costing more than it saves on `bmc-ibm-12` | measured (classic) |
| **DEC-31** | Analysis | Reason-side bumping for learned clauses of at most 32 literals, plus the lucky-assignment check before search | Bump analyzed variables only | Held-out 10.3 s → 8.9 s, `bmc-ibm-12` 1.5 → 0.9 s, `hole10` 1.1 → 0.4 s; the lucky check costs one propagation per attempt | measured (all sets) |
| **DEC-32** | Proof | No proof event is dispatched while no consumer is attached; a tracer attached later adopts every live clause | Allocate a proof id per clause unconditionally | A third of the instructions of a proof-free run's read-and-preprocess phase on a 114k-clause formula, and the same tax per learned clause; parse and setup of `e0ddr2` 0.05 → 0.01 s, held-out 8.9 → 8.4 s | measured (callgrind, all sets) |
| **DEC-33** | Simplification | `gate` and `congruence` out of the default pipeline; transitive reduction at 2 visits per edge | Keep both (congruence found no equivalence in the default order; gate copied every clause for it) | Preprocessing of `bmc-ibm-12` 0.35 → 0.23 s, identical conflict counts | measured (classic) |
| **DEC-34** | Phases | Saved phases only | Target phases (decisions follow the deepest assignment since the last rephase point), with and without rephasing the saved phases to it | `ii16a1` and `bmc-ibm-13` gained; the held-out, heavy and structured sets all lost, in both variants | measured, rejected |
| **DEC-35** | Local search | Near-miss rules: past the third opening round only a walk within two unsatisfied clauses continues; a re-walk improves only by a near miss or a quarter; the opening walk's phases are adopted only on a near miss | Any decrease counts as improvement and is adopted | `bmc-ibm-13` 1.0 → 0.33 s, `ais12` 12,004 → 7,580 conflicts; structured subset 3.8 → 3.4 s, held-out unchanged | measured |
| **DEC-36** | Probing | Failed-literal probing of every variable with a binary occurrence, both polarities, with lifting, before the search; cheap first round, four times the budget after a productive one; skipped under proof consumers | Root-only probing (found no candidate on these encodings); a fixed budget (cost the random set 3%) | Validated effect small once the lifting defect (DEC-37a) was fixed: structured subset within noise, random sets unchanged; kept for the units it derives (`bmc-ibm-13`: 131) at a cost the adaptive budget keeps negligible | measured |
| **DEC-37** | Soundness | A root conflict found before the search sets `root_refuted_` and the solve entry reports it | Rely on the search to rediscover it | The propagator does not rediscover a consumed conflict; `ssa6288-047` was answered with an invalid model before the fix | correctness |
| **DEC-37a** | Soundness | Lifting marks are cleared on every exit from a probe | Clear them only after a completed negative probe | Marks left by a positive probe at an effort-budget exit lifted a wrong unit on `bmc-ibm-1/12/13` (answered unsatisfiable); caught by the comparison script's manifest check | correctness |
| **DEC-39** | Reduction | A use counts two in the clause header; the pass leaves one as grace for mid-glue clauses and clears it the pass after | Grace written back as the same count that means "used" | A used mid-glue clause was protected from reduction forever; pinned by `reduce_protection_test` | correctness of the policy |
| **DEC-40** | Simplification | Fresh factoring variables are numbered above the problem's highest variable, passed down by the scheduler | Above the database's highest occurrence | A clause-free problem variable (header-declared, assumption-only, or freed) was reused as a definition variable; found by `pass_equivalence_test` | correctness |
| **DEC-42** | Solve entry | The first phase searches, budgeted at two propagated assignments per literal (the lucky check's attempts not charged) and 500 conflicts, with inprocessing refused inside it | Lucky check only (a 200-conflict probe charged the smallest random instances 4-6%) | Decides the classic circuit/planning/scheduling instances before preprocessing: `bmc-ibm-1` 88 → 19 ms, `logistics_d` 29 → 9, `bw_large_c` 41 → 10; structured 25 2.69 → 1.84 s, hard and held-out within 1% | measured (GCC vs GCC, medians of 3) |
| **DEC-43** | Local search | No walk in an episode where probing derived a unit | Walk everywhere (`hanoi4`: 46 ms of walking for a 14 ms search) | Walk-solved formulas all have zero probe units; `hanoi4` 66 → 20 ms, `hanoi5` 0.47 → 0.35 s, `bmc-ibm-13` 0.51 → 0.22 s | measured |
| **DEC-44** | Phases | The lucky check restores the pre-probing phase snapshot on every formula | Restore only when an opening walk is pending (the last lucky attempt's phases leaked otherwise) | `bmc-ibm-13`, `bw_large_d`, `3bitadd_32` gain; `hole9` 61 → 107 ms; the alternatives (old semantics, seeding from the furthest attempt) cost `bmc-ibm-13` 0.81 s / 2.6x | measured |
| **DEC-45** | Probing | Every variable with a binary occurrence keeps both probes | Skip literals implied by a non-failing probe (CaDiCaL's roots) | Lifting needs both implied sets and the lifted units are most of the units on the BMC/blocks-world formulas: `bmc-ibm-13` 0.53 → 0.90 s | measured, rejected |
| **DEC-46** | Engine | Fixed-capacity trail (`bank/trail.hpp`), clause reference resolved once and counters settled per partition in propagation, clause minimization on an explicit stack | `std::vector` trail, recursion | Code that the link-time optimizer compiles the same way in every build: one build had inlined the vector's growth path into the propagation loop (a sixth more instructions per call) and folded one recursion level of minimization (0.9 M against 1.4 M calls) | measured (instruction counts) |
| **DEC-48** | Simplification | The forward subsumer skips pairs of clauses it checked in an earlier run that have not changed since (a header flag the storage clears on every body rewrite), scanning an index of fresh clauses for a checked one | A full pass at every inprocessing epoch | Exactly the full pass's result (pinned by `pass_equivalence_test` and identical search statistics); `bmc-ibm-12` 948 → 859 ms, `uuf250_01` 588 → 577 | measured |
| **DEC-49** | Engine | Occurrence lists counted before they are filled (factorizer), the storage's clause accessors inlined by attribute, watch lists pre-sized with an eighth of slack | Lists grown a push at a time, accessors left to the inliner, exact pre-sizing | Identical statistics on twelve instances; 2% fewer instructions on the smallest runs (`dubois100`), where 3,800 allocations were a tenth of the work | measured (instruction counts) |
| **DEC-47** | Build | Performance builds use the GCC profile explicitly | The default qbs profile (clang on this machine) | Same source, same instruction count, 5-8% slower on the walker under clang | measured |
| **DEC-41** | Solve entry | A first phase on the formula as stated: propagation state, lucky check and root propagation before any preprocessing, with the arena bytes, heap, phases and counters snapshotted and restored if it does not decide the instance | Preprocess first (the previous order); a first phase that kept its state | The second phase is provably the run it would have been (identical decision counts at fixed conflict limits); instances decided in the first phase skip the pipeline: `ais12` 68 → 2 ms, `e0ddr2` 47 → 20 ms, `bmc-ibm-7` 32 → 9 ms; the others are unchanged by construction | measured (trajectory-identical) |
| **DEC-38** | Restarts | Stable/focused alternation: Luby base 64 and the configured base in periods from 2,000 conflicts doubling, focused first | One schedule; stable-heavy periods; a gentler focused interval starting stable | Validated with every answer checked: structured subset 4.07 → 3.15 s, heavy 5.04 → 4.04 s, hard 2.26 → 2.07 s, `hanoi5` 1.2 → 0.56 s, at 6% on the random held-out set; the two alternatives lost on every set | measured (interleaved, repeated) |
| **DEC-27** | Simplification | `decomposition` and `congruence` off by default | Fix `equivalence_substitutor` (polarity, duplicate removal, reconstruction witness) | The classic SATLIB set exposed a wrong model on `bmc-ibm-13`; the substitutor needs a redesign, so the passes are opt-in until then | correctness |
| **DEC-26** | Build | No PGO | `-fprofile-use` | Trained on six instances, no gain (3.91 s vs 3.75 s on the unsat set), like `-march=native` before it | measured |
